5. HOW TLS PROVIDES CONFIDENTIALITY AND INTEGRITY
--------------------------------------------------

5.1 Confidentiality
TLS provides confidentiality through:

a) Symmetric Encryption:
   - After the handshake, all application data is encrypted using a symmetric cipher (e.g., AES)
   - The symmetric key is derived from the pre-master secret and random values
   - Only the client and server know the encryption keys

b) Key Exchange:
   - The pre-master secret is securely exchanged using asymmetric encryption (RSA) or key agreement (ECDHE/DHE)
   - Even if the handshake is intercepted, the pre-master secret cannot be recovered without the server's private key

c) Perfect Forward Secrecy (with ECDHE/DHE):
   - Each session uses a unique ephemeral key pair
   - Compromising the server's long-term private key does not allow decryption of past sessions

5.2 Integrity
TLS provides integrity through:

a) Message Authentication Code (MAC):
   - Each encrypted record includes a MAC computed using a hash function (e.g., SHA-256, SHA-384)
   - The MAC is computed over the encrypted data and a sequence number
   - Any modification to the data will result in an invalid MAC, causing the connection to be terminated

b) Authenticated Encryption (with GCM/CCM modes):
   - Modern cipher suites use authenticated encryption modes (AES-GCM, AES-CCM)
   - These modes provide both encryption and authentication in a single operation
   - More efficient than separate encryption and MAC

c) Certificate Chain Verification:
   - The server's certificate is verified against trusted root CAs
   - This ensures the server is authentic and prevents man-in-the-middle attacks
   - Certificate pinning can provide additional protection

d) Handshake Verification:
   - The Finished messages contain a hash of all handshake messages
   - This ensures the handshake was not tampered with
   - Both parties verify the Finished messages match

5.3 Additional Security Features

- Sequence Numbers: Prevent replay attacks
- Random Values: Ensure uniqueness of each session
- Alert Protocol: Allows secure error reporting
- Renegotiation Protection: Prevents certain attacks on TLS renegotiation
